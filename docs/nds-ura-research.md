The standalone ROM/BPS is in `out/nds-research/sf1-ura-exe6-v1/`.
It selects URA at title, ordinary virus battle 21 and synthetic communication
dispatch, using appended song 474 on Japanese EXE6 Gregar. On 2026-10-17

rematches were not separately reported.

`bedd1fdf1703a521f23b01a0e6896dd840d3ccc826e93e6585cf4162ea7c9be3`.

## Conflict and correction

Source: Japanese `ssr1d.nds`, SDAT 667, SSEQ 18 `BGM18URA`, sequence file 17,
bank 39, volume 70, source player 0. The eight tracks use ten PCM sample/root
contexts. Tempo 112 maps to native 112 (89.193068 ticks/second); gain remains
+3.5 dB, with ten PCM voices at 10,512 Hz. No active pitch-LFO mode or fitted
attack mode is needed. Standard PCM8/envelope/tempo and voice allocation
approximations remain.

Track 7 first uses instrument 123, original key 96, as long-note alias 127.
Track 3 later uses that same instrument and alias for original key 60.
The source instrument selects different samples: key 96 uses wave 75,
root 84; key 60 uses wave 91, root 60. The old shared rhythm bank could not
store both child-tone definitions at the same `(voice, alias)` slot, and
correctly refused conversion. The v8 scan records that failure.

The compiler now retains a set of compatible rhythm banks for each original
instrument/pan/envelope context. It reuses the first bank whose selected key
is empty or already maps to the same source key. Only a conflicting slot
creates another bank. Source keys, samples, tuning, note times, gates and
track-local aliases remain intact. URA uses six native instrument contexts:
voice 4 holds instrument 123's key-96 alias, voice 5 its key-60 alias.
Both use alias 127, independently stoppable on their respective tracks.
The report records this single split at tick 791 in `voice_context_splits`.

This is a rhythm-bank allocation correction; it does not raise sequence-track
or PCM-channel capacity. The 128-voice bank bound, overlapping long-alias
rejection, matching loop-carry requirement and final raw child-tone conflict
guard still apply. Previously valid allocations retain their first bank and
their generated bytes.

The generated loop starts at 864 with period 1,536. Five long-note intervals
carry across the common cut on tracks 3/4/5/7. The independent decoder checks
the intro and two complete loop periods, extending gates through at most
tick 4,608. The actual first GOTO is at 2,400 (26.91 seconds), followed by
44.13, 61.35, 78.57 seconds and every approximately 17.22 seconds.

## Evidence and limits

- All 210 regression tests pass. Synthetic two-track tests cover conflicting
  source keys sharing one alias, compatible aliases sharing the existing bank,
  preserved child-tone pitch keys and independent EOTs. The actual URA test
  checks the split, original-data preservation, BPS reconstruction, eight
  tracks, ten samples, six instruments and five loop carries.
- All eighteen previously accepted experiment ROMs and BPS patches rebuild
  byte-identically; see `prior-regressions.json`.
- The independent 180-second DS software reference matches 1,846 notes on
  all eight tracks, 15,882 pan/bend/expression/delay controls and ten decoded
  PCM sample/root comparisons. At least two complete source loops per track
  are covered; the reference's coarse maximum allocation is thirteen voices.
- `natural-loop/validation.json` checks the original eight-track ROM's intro
  and one complete generated loop: 1,609 natural frames, clock 2,402, all
  ten sample pointers and changing PCM output. Track states agree with the
  independent decoder. No registers/RAM are edited, no headers redirected
  and no restart occurs. Later complete native cycles remain untested.
- `native-aliases/validation.json`, reproduced by `probe-native-aliases.py`
  in the artifact directory, follows actual PCM channels through clock 2,989.
  Track 3's alias matches its wave in 866 observations; track 7's in 2,014.
  Both distinct waves are present simultaneously in 842 observations.
  Across clocks 2,400/2,402, track 3 stays in slot 0 and track 7 in slot 8,
  both with active flags 17 and their own wave pointers. Following track 3's
  EOT at 2,956, its channel has release flags 81 while track 7 remains active
  with flags 17. This confirms independent alias identity, first-jump
  continuity and track-local stopping in the actual arrangement. It uses a
  disposable copy of the exact ROM without register/RAM changes, rather than
  a synthetic song. It does not prove equal DS/GBA mixing or allocation.
- `runtime/` checks effects 100/129, continued music, ordinary/synthetic
  communication dispatch, queued stop, native restoration and three restart
  cycles. These helpers inject PC/LR and do not establish actual linked play
  or complete gameplay transitions.
- `preview/preview.wav` captures 30 seconds of native output (peak 12,281).
  `comparison/listen.html` provides normalized software-DS/native comparison;
  normalization does not establish waveform fidelity.

The archived v8 audit remains unchanged: its URA row is the earlier rejection,

## Reproduce and listen

Use fresh directories:

```bash
python3 scripts/build_nds_experiment.py \
  --source /home/harp/projects/nds/roms/ssr1d.nds --base ../roms/exe6.gba \
  --song sf1-ura --event 1 --event 21 --event scene:communication \
  --out out/nds-ura-example
mkdir out/nds-ura-example/reference
out/nds-research/reference-player-depth-v2/nds-reference \
  out/nds-ura-example/source.sdat 18 180 out/nds-ura-example/reference
python3 scripts/validate_nds_experiment.py out/nds-ura-example \
  --reference out/nds-ura-example/reference --lifecycle --out out/nds-ura-example/runtime
python3 scripts/validate_song.py out/nds-ura-example/unified.gba \
  --unified out/nds-ura-example/build.json --id 474 --loop-cycles 1 \
  --frames 2400 --out out/nds-ura-example/natural-loop
```

Listen continuously in battle for three minutes. Focus on the two sustained
parts, their sample/pitch identity, and joins near 27/44/61 seconds and later
repetitions. Check for cuts, repeated attacks or hanging notes, use chips and
the Buster, return to the map and start another encounter to check native
restoration and restart. `manual-testing.json` records user-reported acceptance
on 2026-10-17. Instrumented native loop coverage remains one complete cycle.
